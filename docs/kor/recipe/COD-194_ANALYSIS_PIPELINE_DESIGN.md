# COD-194 코드 기반 분석 파이프라인 설계

작성 기준일: `2026-09-18`

목표는 원천 데이터 검증부터 모델 입력 생성과 결과 요약까지 같은 명령으로 재현하는 것이다. 재사용 함수와 실행 명령, 데이터와 출력물을 서로 분리한다.

## 구조

| 경로 | 책임 |
| --- | --- |
| `src/sme_closure_signal/quality.py` | 인코딩·컬럼 표준화, 키·결합률·타깃 품질 검사 |
| `src/sme_closure_signal/dataset.py` | 분기×상권×업종 결합과 `t+1` 타깃 생성 |
| `src/sme_closure_signal/analysis.py` | 기술통계와 평가 함수 |
| `src/sme_closure_signal/cli.py` | `validate`, `build`, `summarize` 단일 실행 진입점 |
| `src/sme_closure_signal/preview.py` | 공식 파이프라인 밖의 구조 확인용 보조 모듈 |
| `data/` | Git에서 제외하는 원천·중간·모델 입력 데이터 |
| `outputs/` | Git에서 제외하는 검증·모델·그림 산출물 |

## 실행 단계

1. `validate`: 스키마, 키 중복·결측, 데이터 간 결합률과 폐업 타깃 분포를 JSON으로 기록한다.
2. `build`: 점포를 기준으로 매출과 길단위인구를 결합하고 연속된 다음 분기의 폐업 발생 타깃을 생성한다.
3. `summarize`: 타깃 가용 행과 분기별 폐업 발생 비율을 집계한다.
4. COD-195에서 결측·극단값·최소 노출 점포 기준을 확정한다.
5. COD-196에서 단순 기준선과 후보 모델을 같은 데이터 계약으로 구현한다.
6. COD-197에서 시간 순서 검증과 결과 이미지·평가표를 생성한다.

## 데이터 계약

- 기본 키: `quarter`, `area_code`, `industry_code`
- 특징 시점: 기준 분기 `t` 이전과 현재 정보만 사용
- 타깃: 연속된 `t+1` 분기의 `closure_count > 0`
- 매출 결측과 길단위인구 결측은 값 대체 전에 별도 플래그로 보존
- 학습·검증 파일은 무작위가 아닌 시간 순서로 분리
- 원천 CSV, 인증키, 재생성 가능한 모델 입력과 출력은 커밋하지 않음
