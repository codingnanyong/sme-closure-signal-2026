# Work Studio 지원 분석 재현 인계

최초 작성일: `2026-10-14`. COD-197·201~203의 지원 자료다. `2026-10-19`에 CSV 3개 등록·Load·Script with Jupyter 모델 실행을 완료했다. 아래 절차는 최초 계획이며, 실제 실행과 환경 차이는 [실행 검증 기록](../project/WORK_STUDIO_EXECUTION_2026-10-19.md)을 따른다. 포털 출품 제출은 수행하지 않았다.

## 준비된 로컬 입력

`python -m sme_closure_signal prepare-submission`으로 `outputs/workstudio/stores-sales-v1/`에 시간 구간을 미리 나눈 CSV를 생성한다. 실제 집계 관측값이므로 원천 이용조건과 포털 데이터 활용 동의를 확인한 뒤 업로드한다. 기본 제출 검토 묶음에는 이 실제 관측 CSV를 포함하지 않는다.

| 파일 | 피처 분기 | 타깃 분기 | 예상 행 수 |
| --- | --- | --- | ---: |
| train.csv | 2024Q1~Q4 | 2024Q2~2025Q1 | 296,131 |
| validation.csv | 2025Q1 | 2025Q2 | 73,647 |
| test.csv | 2025Q2~Q3 | 2025Q3~Q4 | 147,032 |

인코딩은 UTF-8 BOM, 구분자는 쉼표다. quarter·area_code·industry_code는 문자열, closure_next_q는 0·1 정수로 읽는다. 분기·상권·업종과 점포 수는 추적·집단 검토용이고 최종 모델 피처는 `log_stores`, `log_closures`, `log_openings`, `industry_code`다. 타깃·키를 수치 피처로 자동 투입하지 않는다.

## 6단계 대조 절차

1. 세 입력을 별도로 불러와 행 수·자료형·키 중복·타깃 분포를 확인한다. 무작위 분할하지 않는다.
2. 학습 자료에서만 수치 변수 중앙값·표준화 계수와 업종 인코더를 적합하고 검증·평가에 그대로 적용한다.
3. 로지스틱 회귀와 파라미터를 설정할 수 있는지 실제 Work Studio에서 확인한다. Python 계약은 L2 회귀 C=10, lbfgs, max_iter=1000, 클래스 가중치 없음이다.
4. 검증 점수와 임계값 0.2595459972를 대조한다. 검증 AP 목표는 0.4909605409다. 플랫폼 정규화·목적함수·C 정의가 다르면 동일 모델이라고 표현하지 않는다.
5. 평가 AP 0.4862183778, F1 0.4662723383, 상위 20% 포착률 0.6390614673을 대조한다. AP와 사다리꼴 PR-AUC를 구분하고 동점 처리 차이를 기록한다.
6. 점포 규모별 표본과 성능, 위험 5분위, 두 모델의 AP 차이를 Python 근거와 연결한다. 실행일·블록명·파라미터·불일치 원인·실제 화면을 로컬 증빙으로 보관한다.

## 지원되지 않는 기능의 처리

로컬 가이드에서 확인된 것은 데이터 입력·전처리·분할·랜덤 포레스트·분류 평가다. 로지스틱 회귀, 학습 자료 기준 인코더 재사용, AP, 군집 재표집 블록이 모두 제공된다고 확인한 것은 아니다. 미지원이면 가능한 데이터 품질·집계·차트 경로를 재현하고, 모델 부분은 지원되는 실행 방식이나 공식 허용 범위를 확인한다. 랜덤 포레스트로 바꿔 실행한 값을 기존 회귀의 재현으로 표기하지 않는다.

참가신청서 공통 문구와 유형별 제출 항목의 차이는 [공모 요건](../project/COMPETITION_REQUIREMENTS.md)에 남아 있다. 최종 포털 요건 확인과 사람 검토 이전에 Work Studio 실행 완료·최종 제출 완료로 표시하지 않는다.
