로컬 파일·원본 크기 가독성·한국어 캡션과 분석표 대조는 통과했다. 포털 첨부 허용 형식·용량·픽셀 제한 및 실제 축소 렌더링은 로그인 필요로 미확인이다. 따라서 COD-200 전체 완료를 주장하지 않는다.

## 수치·캡션 검사

- 캡션 출처: `docs/kor/research/COD-199_VALIDATED_INSIGHTS.md`의 COD-200 그림과 캡션 표.
- 매출 제외 AP 0.486218 및 상권 재표집 구간 [0.466027, 0.505963]은 `area_bootstrap_intervals.csv`와 일치한다. 전체−매출 제외 차이 −0.000613 및 구간 [−0.001035, −0.000162]도 문서와 일치한다. 재학습 불확실성·인과효과·독립 확증 검증으로 확대 해석하지 않는 설명을 유지한다.
- 소규모 1~5개 집단의 전역/규모별 임계값 적용 정밀도 32.5744%/15.0138%, 재현율 3.3653%/32.4588%, 점검량 571/11,949행은 `size_threshold_policies.csv`와 일치한다. 같은 점검 예산 비교가 아니라는 캡션이 필요하다. 현재 그림에는 점검량 패널이 없으므로 본문 수치를 함께 제시한다.
- 업종 그림의 가로축은 로그 스케일의 평가 행 수, 세로축은 AP이며 캡션과 일치한다. 업종별 양성 비율 차이 때문에 단순 순위나 자치구 검증으로 설명하지 않는다.
- 위험 분위 그림은 `quintiles.csv`의 2025Q2 1.6310%→34.2644%, 2025Q3 1.2116%→31.5069%와 일치하며 두 분기 모두 단조 증가한다. 상권×업종 집계 행의 다음 분기 폐업 발생률이며 개별 점포 폐업확률이 아니다.
- 그림은 로컬 평가 결과다. Studio AP 0.4862426327과 혼용하지 않으며 모델 완전 동등성 not_exact를 유지한다.

## 가독성 권장

그림 내부는 영어·코드 표기다. 원본에서 읽을 수 있지만 제출 화면에서는 한국어 캡션과 함께 `no_sales=매출 제외`, `full=전체 후보`, `exposure_industry=점포 수·업종 기준선`, `20252=2025년 2분기`, `20253=2025년 3분기`를 설명하는 것이 좋다. `no_sales_fixed_c`는 이번 선택 C가 같아 매출 제외 후보와 동일 수치인 비교 행이다. 가로로 긴 임계값 그림은 포털 축소 표시에서 별도 가독성 확인이 필요하다.

## 포털 직접 확인 결과·남은 작업

- 제공된 분석 화면 주소 `https://anals.datahub.tips/home?mode=popup`는 이번 접근에서 403 Forbidden을 반환했다.
- 공식 공고 페이지 `https://www.kdata.or.kr/datahub/portal/support/board/10/48`는 접근 가능했다.
- 공식 메뉴 ‘활용사례 찾기 → 레시피 직접 생성’은 ‘로그인이 필요한 서비스’ 안내 후 로그인 화면으로 이동했다. 현재 로그인 세션이 없어 작성 폼의 첨부 조건을 읽을 수 없었다.
- 로그인 후 작성 폼의 허용 확장자·최대 파일 크기·최대 개수·픽셀 제한을 확인하고 실제 표시를 점검해야 한다. 파일 업로드·등록·공개는 이번 읽기 점검에서 수행하지 않았다.
- 로그인 URL의 일시 토큰 및 계정 정보는 이 보고서에 기록하지 않았다.

이번 점검에서 생성한 파일은 본 보고서뿐이며 기존 그림·소스는 변경하지 않았다. 최초에는 outputs 경로에 보관했으며, 집에서 이어가기 위해 docs/kor/project/로 이동해 저장소에서 관리한다. 실제 그림·원천은 Git 제외 경로에 유지한다.

## 로그인 후 재점검

사용자가 열어둔 경진대회 접수 화면에서 로그인 상태를 확인하고 공식 메뉴로 레시피 직접 생성 화면에 접근했다. 위 로그인 차단은 이전 점검 이력이며 현재 해소됐다.

- 접수 화면은 `(2026) 데이터레시피 제안`을 선택한 상태이며 제출자료는 기존 데이터레시피를 조회해 연결하는 구조다. 결과 PNG를 접수 신청서에 바로 붙이는 구조가 아니다.
- 레시피 작성 화면: `https://www.kdata.or.kr/datahub/portal/data/data-recipe/create`.
- 입력 내용을 저장하지 않고 ‘다음으로’로 이동해 6단계 ‘분석 결과 예시’를 확인했다. 초기 예시 2개 각각에 파일 업로드 영역과 필수 설명 입력란이 있고 ‘분석결과 예시 추가’ 버튼이 있다.
- 이 단계의 화면에는 파일 형식·최대 바이트·최대 픽셀 제한이 표시되지 않는다. DOM의 파일 입력에도 `accept` 속성이 없고 `multiple`만 있다. 이 사실은 서버가 모든 형식·크기를 허용한다는 증거가 아니다.
- 기존 공식 가이드 검토 기록의 최대 5개에 비해 후보 이미지 4개는 개수 범위 내다. 현행 화면에서 최대 5개 제한을 실제로 시험한 것은 아니다.
- 이용가이드 모달은 ‘No PDF file specified.’를 표시했고 상세가이드 다운로드는 응답하지 않아 최신 추가 제한을 확인하지 못했다.
- 파일을 첨부하지 않았으므로 서버의 PNG 수용 여부·업로드 후 미리보기 축소 가독성은 미확인이다. 따라서 판정은 **로컬 검사 통과 / 포털 입력 구조 확인 / 서버 수용·실제 표시 미확인**이다.
- 레시피 임시저장·등록·경진대회 제출·동의는 수행하지 않았다. 개인 정보나 인증 토큰을 기록하지 않았다.
